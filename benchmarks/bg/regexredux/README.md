# regexredux

`setup(n)` (untimed): BG fasta's output for n, generated by each port (same bytes; n = 1000 is BG's `regexredux-input.txt`).
`bench(n)`: regex-redux over it — strip headers and newlines, count the nine variant patterns, apply the five
replacements in order, report the three lengths; returns FNV-1a (32-bit) of the bytes BG prints.
n = 500,000 (5.08 MB of input; BG: 5,000,000). n = 1000 gives 2596312850 = FNV of BG's `regexredux-output.txt` (checked for every port).
Run: `node scripts/benchmark-bg.mjs regexredux`.

## Regex engines

Regex-redux measures a regex engine more than a language. The fastest BG programs all call PCRE2 with its JIT
(C, C++, Rust via pcre2-sys, Haskell and Java via FFI, Go via a cgo binding); none of that JIT exists in Wasm.
So each port uses what that language has in Wasm:

| port | source | engine | adapted |
|---|---|---|---|
| c | BG gcc #5 (Zerfas, Herczeg) | PCRE2 10.45 interpreter (`pcre2_match`), vendored in `pcre2/`, built by emcc with the port (`c/pcre2_lib.c`, no JIT, no Unicode) | OpenMP blocks in order; `pcre2_jit_compile` dropped, `pcre2_jit_match` → `pcre2_match`; stdin → setup's text; `printf` → `snprintf` + FNV |
| cpp | BG g++ #6 (Lenger) | PCRE2 interpreter, as c (`cpp/pcre2_lib.c`, compiled as C) | `std::async` deferred (runs in order); no JIT/JIT stack; `boost::noncopyable` → deleted copy operations; `std::cout` → `std::ostringstream` + FNV |
| rust | BG Rust #7 (Kaitchuck, Machida) | the `regex` crate (`regex::bytes`) | pcre2-sys (C + JIT) does not build for wasm32-unknown-unknown: module `pcre2` keeps its API (`find_at`, `count`, `replace`, `replace_inplace`) over `regex`; rayon/channels in order |
| go | BG Go #5 | Go's `regexp` | `github.com/GRbit/go-pcre` is cgo (none on wasip1) → `regexp.MustCompile`, `FindIndex`, `ReplaceAll`; goroutines in order |
| swift | BG Swift #4 | Foundation `NSRegularExpression` (ICU) | as BG; Dispatch tasks in order; Foundation + ICU ship in the module (51 MB) |
| haskell | BG GHC #3 (Reinders, after gcc #5) | PCRE2 interpreter through the FFI, `haskell/pcre2_lib.c` compiled and linked by GHC (wasi-sdk clang, `-optc-O3`) | no JIT (the `capi` import of `PCRE2_JIT_COMPLETE` goes); `Data.Vector.Storable` (vector is not in the wasm toolchain's packages) → a raw `Ptr Word8` buffer grown with `reallocBytes`; threads/MVars in order |
| dart | BG Dart #5 (Gouy) | dart2wasm's `RegExp` = the host's JavaScript RegExp (V8 Irregexp) via JS interop | isolate in order; `dart compile wasm -O2` |
| js | BG Node #3 (Millikan, …, Filatkin) | V8 Irregexp (JIT) | worker in order |
| kotlin | not on BG: from BG Java GraalVM #4 | `kotlin.text.Regex` (Kotlin/Wasm's own engine, in the module) | Java calls PCRE2 by FFM; same steps (cleanup, LinkedHashMap of replacements, counts) |
| moonbit | not on BG: from BG Node #3 | MoonBit core `@string.Regex` (in the module) | `.` matches a newline in MoonBit, so the cleanup pattern is `>[^\n]*\n|\n` (as BG C++/Rust/Swift write it) |
| assemblyscript | not on BG: gcc #5's steps | **hand-written matcher** (same as utu's) | AssemblyScript has no RegExp; `assemblyscript-regex` copies the rest of the subject at every start position (`str.substr`), quadratic on 5 MB, so it is not usable here |
| utu | gcc #5's steps | **hand-written matcher in utu** (`regexredux.utu`) | utu has no regex library: a shift-and (bitap) scan for fixed-width patterns without `*` (the nine counts, the first three replacements) and a small backtracking matcher for the rest, for exactly the constructs these patterns use (literals, `\c`, `.`, `[...]`, `[^...]`, greedy `*`, top-level `|`; leftmost match, first alternative, as PCRE). Text in one byte `mem` |
| utu host | Node #3's calls | the host's RegExp (V8 Irregexp) through `@es` (`regexredux.host.utu`) | the text is one JS string made in setup; each count/replace is one host call |

All ports generate the input with their own copy of BG fasta's algorithm (double cumulative probabilities); utu's
generator is the block from `../fasta/fasta.utu`. No port uses SIMD explicitly.

(Exact numbers: `results.json` here; the table is one run.)

Frontier (ms vs gzip): JavaScript (1.0 KB, 161 ms) dominates: V8's JIT-compiled Irregexp is the fastest engine here and
the engine itself is not counted. Among self-contained modules: utu smallUnsafe (2.6 KB, 661 ms, the hand-written
matcher), MoonBit (24 KB, 372 ms), Rust (394 KB, 251 ms). utu host (3.1 KB, 126 ms) runs on the same Irregexp as JS.
Among real regex engines shipped in Wasm, Rust's `regex` is fastest; PCRE2's interpreter (C, C++, Haskell) is 5-7x
slower, Go's `regexp` 70x.

## Caveats

- The comparison is engine against engine. JS, Dart and "utu host" run V8's JIT-compiled Irregexp; everything else
  interprets (PCRE2's interpreter in C/C++/Haskell, Rust's `regex` automata, Go's `regexp`, ICU, Kotlin's and MoonBit's
  engines). BG's native numbers come from PCRE2's JIT, which Wasm cannot have.
- utu and AssemblyScript do not run a regex library at all: their matcher handles only these patterns' constructs
  (no groups, `+`, `?`, anchors, ranges). It is a fair regex-redux port of the matching work but not a general engine,
  and its size (a few KB) reflects that. The headline utu number is that matcher; "utu host" is reported apart.
- Rust's 1.2 MB is mostly the `regex` crate's Unicode tables (default features, as BG's Rust programs use the crate).
- Swift ships Foundation and ICU (51 MB); Go, Haskell their runtimes; Dart and Kotlin their JS runtimes. JavaScript's
  size is its source only; the engine is assumed.
