# revcomp

`setup(n)` (untimed): the fasta output for n, generated by each port with its own language's
fasta generator (copied from `../fasta/<lang>/` between the `---- fasta generator` markers, its
sink appending to an input buffer). `bench(n)`: BG reverse-complement of that input, read as from
stdin (each port copies it in as its stdin reads would; the input is never mutated); returns
FNV-1a of the bytes BG prints. n = 5,000,000: 50.8 MB in (BG: fasta 25,000,000, 254 MB).
Checked: n = 1000 gives 3542197540 = FNV of BG's `revcomp-output.txt`; n = 5M matches BG gcc #7
built natively on the native fasta output. Run: `node scripts/benchmark-bg.mjs revcomp`.

## Ports

| port | source | adapted |
|---|---|---|
| c | BG gcc #7 (Zerfas): chunks rear to front into a per-thread buffer, SSE4.1 16-byte reverse-complement, 2-byte lookup table | pthreads removed (one thread takes the chunks in order); chunk buffer static; `read` → copy from input; SSE4.1 via Emscripten (`-msse4.1`) |
| cpp | BG g++ #2 (Kewley): iostream reads, in-place SIMD swap | `std::cin` → istream over the input (a streambuf get area), `std::cout` → hashing streambuf; `-DSIMD -msse4.1` as BG |
| rust | BG Rust #1 (Machida): 64 KiB reader, in-place left/right swap, SSSE3 | rayon spawns run in order; SSSE3 module on `core::arch::wasm32` (`_mm_shuffle_epi8` = swizzle of index & 0x8F, as Emscripten); stdin = `&[u8]` (implements `Read`); memchr crate kept |
| go | BG Go #6 | ncpu = 1; worker/writer goroutines → direct calls; stdin = `bufio.Reader` over `bytes.Reader` |
| swift | BG Swift #1 | Dispatch removed; `fread` → copy from input; no Foundation |
| haskell | BG GHC #4 | `hGetBuf stdin` → copy from input (same contract); `hPutBuf` → FNV; buffer freed per call |
| dart | BG Dart #5 | isolates removed; stdin → 64 KiB `sublist` blocks (BG's code needs ≤ one `>` per block: n ≥ 33,000) |
| js | BG Node #2 | stdin → 16,000-byte copies, `read()` driven as the readable events; Buffer → Uint8Array (`slice` → `subarray`); state reset per call |
| kotlin | not on BG: from Java GraalVM #6 | ForkJoin tasks run as created (disjoint ranges); `System.in.read` → copy of input |
| moonbit | not on BG: from Rust #1 (fastest), its scalar `fallback` reverse_chunks (no SIMD) | slices as (start, length) on one `FixedArray[Byte]` |
| assemblyscript | not on BG: from Rust #1 with its SSSE3 path | raw memory; shuffle_epi8 as Emscripten's; constant reverse as `i8x16.shuffle` |
| utu | Rust #1's algorithm, scalar `fallback` reverse_chunks | idiomatic: `mem` U8 buffers; copies are byte loops (a mem has no bulk copy) |

SIMD: c, cpp, rust, assemblyscript (16-byte reverse + 2 table shuffles); the rest scalar.
No `revcomp.tuned.utu`: SIMD here needs 16-byte loads/stores from the buffer, and utu's `@wat`
cannot touch memory and there is no V128 mem kind, so a tuned version would rebuild each vector
from 16 byte reads.

## Caveats

- Every size includes the port's fasta generator (setup), which revcomp itself doesn't need:
  roughly the fasta port's size (utu ~1–2 KB, C ~3 KB gzip).
- FNV over the ~50 MB output is a large, equal share of every port's time.
- utu's safe builds (fast, small) are 34% slower than the unsafe ones: per-access checks.
- utu copies input with byte loops (no `memory.copy` for mems), where C/Rust/AS use memcpy.
- C++ ships iostream (141 KB wasm, WASI imports); its time is mostly `getline` reading.
- BG's fastest programs are parallel; all ports here are single-threaded.
- Go, Swift, Haskell ship runtimes (and `../wasi.js`); Dart and Kotlin their JS runtimes;
  JavaScript's size is its source only.


Update (2026-11-05): `revcomp.utu` reads its input 8 bytes per step (copy and the `>` test in one pass, the bytes packed into two words): smallUnsafe ~129 -> ~97 ms. The byte-at-a-time version is `alt/revcomp-bytewise.utu`; `alt/revcomp-fused-hash.utu` (~81 ms) also hashes while it writes, which the other ports do not, so it is not the headline. utu numbers are in results.json.
