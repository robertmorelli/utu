# A little more focus

A browser task board written in UTU, using the generated TypeScript browser ABI.
DOM construction, event handlers, mutable task state, JSON and localStorage all
live in `main.utu`. There is no application-specific JavaScript or inline `@es`.
The JavaScript loader and host-call wrappers are generated by the generic builder.

```sh
bun install
bun run build
bun run demo:serve
```

Open the localhost URL printed by the last command. `bun run demo:build` writes
`dist/browser-board/{index.html,style.css,app.js,app.wasm,sizes.json}` for any static
HTTP server. Serve `.wasm` as `application/wasm`. Use a browser with WasmGC and JS
string builtins; the automated test uses Chromium.

```sh
bunx playwright install chromium
node scripts/test-dts-browser.mjs
```

The test builds the app, adds/completes/deletes tasks, checks persistence after a
reload, checks that user input remains literal text, verifies mobile width, and
writes desktop/mobile screenshots and measured code sizes to `dist/browser-board`.
It also times 200 inserts plus 203 toggles with persistence and enforces a 6 KB
gzip budget for the combined Wasm and JS. HTML/CSS are not included in that code
budget. Local storage is expected to be available and contain this app's JSON.

See [the ABI design and limitations](../../docs/typescript-abi.md) for the type
mapping, universal callback bridge, package tests, and compiler/app size tradeoff.
